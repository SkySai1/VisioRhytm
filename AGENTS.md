# Назначение

Разработать нативное desktop-приложение под macOS для визуального анализа того, как текст песни укладывается в заданный ритм.

Приложение не является нотным редактором, DAW или MIDI-секвенсором. Его задача — дать автору текста простую визуальную модель:

- сколько места занимает строка;
- насколько плотно расположены слоги;
- где строку потребуется произносить быстрее;
- где остаётся пространство для растягивания слогов;
- насколько разные строки куплета или припева совпадают по ритмической плотности.

Основной сценарий использования — подготовка lyrics перед генерацией песни в AI-моделях, где пользователь не управляет точной мелодией, но хочет заранее понимать, насколько естественно текст может лечь на выбранные BPM и time signature.

---

# Технологический стек

Приложение должно быть нативным для macOS.

Основной стек:

- Swift;
- SwiftUI;
- AVFoundation / AVAudioEngine для метронома;
- Observation / Observable-модели для состояния UI;
- Codable для формата проекта;
- Foundation NaturalLanguage допускается для вспомогательного анализа текста, но не должно быть обязательной зависимостью алгоритма разбиения на слоги.

Минимальная поддерживаемая версия macOS определяется исходя из актуальной стабильной версии SwiftUI.

Не использовать Electron, React Native или WebView как основу интерфейса.

---

# Основная концепция интерфейса

Главный экран представляет собой горизонтальное ритмическое полотно.

По горизонтали располагается время:

`такт → доля → subdivision`

По вертикали располагаются строки lyrics.

Пример:

```text
                 Такт 1                            Такт 2

          1       &       2       &       3       &       4       &
          │       │       │       │       │       │       │       │

Строка 1  Вой     на      на      не      ви      ди      мом     фрон→

Строка 2  Где     враг            рас     тво     ря      ет      ся

Строка 3  Мы      стро    им              за      щи      ту      ...
```

Это не музыкальная партитура.

Вертикальное положение элемента не кодирует высоту ноты.

Единственное значимое измерение — горизонтальное время.

# Основные сущности

## Project

Содержит:

```swift
Project
- id
- title
- bpm
- timeSignature
- subdivision
- lyrics
- lines[]
- metronomeSettings
```

## TimeSignature

```swift
TimeSignature
- numerator
- denominator
```

Примеры:

- 4/4
- 3/4
- 6/8
- 12/8

Архитектура не должна быть жёстко привязана к 4/4.

## Subdivision

Определяет детализацию полотна.

Минимально поддержать:

- quarter;
- eighth;
- sixteenth.

Для 4/4:

```text
quarter:
1 | 2 | 3 | 4

eighth:
1 & 2 & 3 & 4 &

sixteenth:
1 e & a 2 e & a 3 e & a 4 e & a
```

Subdivision влияет только на визуальную и логическую сетку.

```swift
- text
```

- текст слога;

# Ввод текста

Пользователь вставляет lyrics целиком в отдельное текстовое поле.

Например:

```text
Война на невидимом фронте
Где враг растворяется в сети
Мы строим защиту сегодня
Чтоб завтра систему спасти
```

После подтверждения приложение:

1. разбивает текст по строкам;
2. игнорирует пустые строки либо сохраняет их как разделители секций;
3. каждую строку разбивает на слова;
4. слова визуально разбивает на слоги;
5. создаёт LyricsLine;
6. размещает полученные слоги на ритмическом полотне.

Исходный текст должен оставаться доступным для редактирования.

---

# Разбиение на слоги

Первый MVP ориентирован прежде всего на русский язык.

Реализовать отдельный сервис:

```swift
protocol SyllabificationService {
    func syllabify(_ word: String) -> [String]
}
```

Архитектура должна позволять добавлять другие языки.

Алгоритм автоматического разбиения может быть эвристическим.

Критически важно предоставить пользователю ручную корректировку.

Например автоматический результат:

```text
не-ви-ди-мом
```

пользователь должен иметь возможность изменить границы, если автоматический анализ оказался неправильным.

Не связывать алгоритм разбиения текста с кодом Canvas.

---

# Ритмическая модель

Основная единица времени внутри приложения не должна быть секундами.

Использовать абстрактные музыкальные ticks.

Например:

```text
PPQ = 480
```

Тогда:

```text
четверть       = 480 ticks
восьмая        = 240 ticks
шестнадцатая   = 120 ticks
```

Это позволит:

- менять BPM без перестройки ритмических позиций;
- менять масштаб;
- синхронизировать метроном;
- в будущем реализовать drag-and-drop;
- поддерживать разные time signature.

BPM используется для преобразования musical time → real time.

---

# Canvas

Canvas является центральной частью приложения.

Он должен:

- отображать такты;
- отображать границы долей;
- отображать subdivision;
- показывать номера тактов;
- показывать текущую позицию метронома;
- поддерживать горизонтальный scroll;
- поддерживать zoom;
- размещать по строкам lyrics.

Разные уровни сетки должны визуально отличаться:

```text
граница такта      — наиболее выраженная;
основная доля      — средняя;
subdivision        — слабая.
```

Не использовать фиксированную ширину такта.

Ширина определяется zoom, а музыкальные позиции остаются независимыми от пикселей.

---

# Метроном

Метроном является центральной функцией приложения.

Настройки:

```text
BPM
Time Signature
Subdivision preview
Volume
Start / Stop
```

Для 4/4:

```text
1 2 3 4
^
primary accent
```

Для 6/8:

```text
1 2 3 4 5 6
^     ^
primary / secondary
```

Метроном должен различать минимум:

- primary accent;
- secondary accent;
- regular beat/subdivision.

Использовать разные pitch или samples кликов.

---

# Синхронизация визуализации

Во время воспроизведения метронома Canvas должен подсвечивать текущую колонку.

Пример:

```text
1   &   2   &   3   &   4   &
        █
```

Подсветка движется синхронно с метрономом.

Дополнительно можно подсвечивать весь текущий beat.

Критически важно:

визуальный таймер не должен самостоятельно определять музыкальное время через `Timer`.

Источником времени должен выступать audio clock / AVAudioEngine.

UI только отображает рассчитанное текущее musical position.

Это необходимо для отсутствия накопительного drift между кликами и визуализацией.

---

# Работа со строками

Главная особенность приложения — индивидуальная настройка плотности каждой строки.

Справа или слева от каждой строки отображается control:

```text
Density
[------●------]

или

Duration:
1 bar
2 bars
3 bars
4 bars
```

Пользователь может определить, сколько музыкального пространства занимает строка.

Например:

```text
"Война на невидимом фронте"

Density 100%

| вой | на | на | не | ви | ди | мом | фрон | те |
```

После уменьшения плотности:

```text
Density 70%

| вой | на |    | не | ви |    | ди | мом | фрон──те |
```

После увеличения:

```text
Density 140%

|вой|на|на|не|ви|ди|мом|фрон|те|
```

Смысл операции:

**Density изменяет горизонтальное распределение текста, но не сам текст.**

---

# Модель плотности

Не привязывать density напрямую к количеству пикселей.

У строки должен быть параметр условной музыкальной длины:

```swift
rhythmicLengthTicks
```

Например:

```text
1 bar
2 bars
4 bars
```

Density является удобным UI-представлением отношения:

```text
количество слогов / rhythmicLength
```

Пользователь должен иметь два способа изменения:

1. явно назначить количество тактов строки;
2. плавно изменить density slider.

Один параметр должен вычисляться из другого.

---

# Распределение слогов

Для MVP автоматическое распределение слогов выполняется равномерно по выделенной строке области.

Например:

```text
10 слогов
2 такта
16 eighth positions
```

Приложение распределяет 10 слогов по 16 позициям.

Важно:

это **не попытка угадать реальный вокальный ритм**.

Это визуальная аппроксимация.

Позднее пользователь сможет вручную:

- двигать слоги;
- растягивать слоги;
- добавлять паузы.

---

# Визуальное представление слога

Каждый слог отображается как небольшой horizontal block:

```text
┌──────┐
│ вой  │
└──────┘
```

Длина блока показывает предполагаемую продолжительность.

Слоги одного слова должны визуально оставаться связанными.

Например:

```text
[не][ви][ди][мом]
```

Граница между словами должна быть заметнее границы между слогами.

---

# Stretch / Compress

В интерфейсе должны визуально различаться три состояния:

```text
compressed
normal
stretched
```

Например:

```text
compressed:

[не][ви][ди][мом]

normal:

[ не ][ ви ][ ди ][ мом ]

stretched:

[   не   ][   ви   ][   ди────── ]
```

Необходимо рассчитывать условный показатель плотности строки.

Например:

```text
syllablesPerBeat
```

и использовать его для визуальной оценки.

Не вводить жёсткие понятия «правильно» и «неправильно».

Допустимо использовать нейтральные категории:

```text
Sparse
Moderate
Dense
Very Dense
```

или числовое значение:

```text
1.4 syllables / beat
2.1 syllables / beat
3.7 syllables / beat
```

---

# Сравнение строк

Очень важный сценарий:

пользователь должен визуально видеть различие плотности соседних строк.

Например:

```text
Verse

Line 1   █████████████           1.4 syll/beat
Line 2   ██████████████████      2.0 syll/beat
Line 3   ██████████████████████  2.8 syll/beat
Line 4   ███████████             1.2 syll/beat
```

Это позволит быстро находить строку, которая существенно выбивается из остальных.

---

# Изменение BPM

При изменении BPM:

не должны изменяться:

- количество тактов;
- позиции слогов;
- rhythmicLength;
- структура Canvas.

Меняется только физическая продолжительность воспроизведения.

Например:

```text
2 bars @ 60 BPM
```

и

```text
2 bars @ 140 BPM
```

занимают одинаковое пространство на Canvas, но проигрываются с разной скоростью.

---

# Изменение Time Signature

При изменении time signature Canvas должен перестроить сетку.

Например:

```text
4/4

| 1 & 2 & 3 & 4 & |

6/8

| 1 2 3 4 5 6 |
```

Lyrics должны оставаться привязанными к musical ticks.

При потенциально неоднозначном преобразовании не уничтожать существующие пользовательские позиции.

---

# Playback

Кнопки:

```text
▶ Play
■ Stop
↺ Return to Start
```

Опционально:

```text
Loop
```

Loop особенно важен для анализа одной строки или нескольких тактов.

Пользователь должен иметь возможность выбрать диапазон:

```text
Bars 5–8
```

и циклически прослушивать метроном с визуальной подсветкой lyrics.

# Редактирование строки

Для каждой LyricsLine:

```text
Text
Bars
Density
Reset
Manual layout
```

Минимальный набор MVP:

- изменение текста;
- изменение количества тактов;
- изменение density;
- повторное автоматическое распределение.

# Manual Mode

На втором этапе добавить ручное редактирование.

Пользователь может:

- перетаскивать слог по timeline;
- растягивать правый край;
- сжимать блок;
- оставлять паузы;
- переносить слоги между тактами.

Snap:

```text
Off
1/4
1/8
1/16
```

Все drag operations должны работать в musical ticks, а не пикселях.

# MusicalPosition

Не хранить позицию как `Double seconds`.

Использовать:

```swift
struct MusicalPosition {
    let ticks: Int64
}
```

Дополнительные вычисляемые свойства:

```text
bar
beat
subdivision
```

Seconds являются производным представлением:

```text
ticks + BPM -> seconds
```

# MVP

Первая рабочая версия должна поддерживать следующий сценарий:

1. Пользователь запускает приложение.
2. Устанавливает:

```text
120 BPM
4/4
1/8 subdivision
```

3. Вставляет lyrics.
4. Приложение автоматически разбивает текст на строки и слоги.
5. Каждая строка появляется отдельной дорожкой.
6. Canvas показывает такты и доли.
7. Пользователь назначает строке:

```text
1 / 2 / 4 bars
```

8. Слоги автоматически распределяются внутри заданного диапазона.
9. Пользователь регулирует плотность строки.
10. Нажимает Play.
11. Слышит метроном.
12. Текущая колонка синхронно подсвечивается.
13. Пользователь визуально определяет:

- где текста слишком много;
- где его мало;
- какие строки отличаются по плотности;
- какие слова потенциально придётся растягивать.

---

# Acceptance Criteria MVP

MVP считается готовым, если:

- BPM можно изменять минимум в диапазоне 40–240;
- поддерживается минимум 4/4, 3/4, 6/8;
- доступны 1/4, 1/8 и 1/16 subdivisions;
- метроном синхронен с визуальной подсветкой;
- после нескольких минут playback отсутствует заметный drift;
- русский текст разбивается на строки и слоги;
- ошибочное разбиение можно исправить вручную;
- каждой строке можно назначить музыкальную длину;
- изменение BPM не изменяет layout;
- изменение density интерактивно перестраивает строку;
- Canvas поддерживает scroll и zoom;
- проект можно сохранить и открыть;
- приложение полностью работает локально без сетевых сервисов.

# UX-принцип

Пользователь не обязан знать музыкальную теорию.

Интерфейс должен объяснять музыкальное время визуально.

Например вместо:

```text
1920 ticks
```

показывать:

```text
1 такт
2 такта
4 такта
```

Вместо требования понимать длительности:

```text
Grid:
Quarter
Eighth
Sixteenth
```

можно дополнительно визуально показывать:

```text
1 2 3 4

1 & 2 & 3 & 4 &

1 e & a 2 e & a ...
```

Внутренние ticks пользователю не показывать.

# Главный принцип продукта

Приложение не отвечает на вопрос:

> «Как именно будет спета эта строка?»

Оно отвечает на более полезный вопрос:

> «Какой объём текста необходимо разместить в этом количестве музыкального времени?»

Это инструмент визуальной оценки rhythmic feasibility lyrics.

Он должен помогать автору увидеть разницу между:

```text
слишком много текста
достаточно пространства
много свободного пространства
```

до передачи lyrics в AI music generator.

Все автоматические расчёты являются подсказкой, а не попыткой предсказать реальную вокальную партию.
