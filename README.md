# VisioRhytm

Нативное приложение для macOS, которое помогает автору песни сравнить объём
текста с доступным музыкальным временем. Строки отображаются на общей временной
сетке, слоги — блоками с предполагаемой длительностью. Можно услышать метроном
и наблюдать синхронную позицию воспроизведения.

Автоматическая раскладка — равномерная визуальная аппроксимация. Она не
предсказывает вокальную партию и не определяет «правильность» текста.
Приложение полностью работает локально; зависимости и сетевые сервисы не нужны.

## Возможности MVP

- BPM 40–240; размеры 4/4, 3/4, 6/8 и 12/8.
- Сетки 1/4, 1/8, 1/16, границы тактов и долей, номера тактов.
- Фиолетовые колонки и отметки кликов метронома, отдельный бирюзовый playhead.
- Русское эвристическое слогоделение и ручная корректировка границ.
- Исключение комментариев в `[]` и `()` из дорожек и расчёта плотности.
- Индивидуальная длина строки: кнопки 1/2/4 такта и непрерывная плотность.
- Кнопки подгонки всех строк под выбранный диапазон тактов и её сброса.
- Сравнение количества слогов на долю, цветовые категории плотности.
- Горизонтальный и вертикальный scroll, масштаб 50–300%.
- Play / Stop / Return, громкость, клики сетки, цикл по диапазону тактов.
- AVAudioEngine / AVAudioSourceNode, три уровня акцента и тихие subdivision-клики.
- JSON-проекты версии 1: открыть, сохранить, сохранить как, локальное autosave.
- Защита несохранённого проекта при открытии, создании нового и выходе.

```bash
swift --version
xcode-select -p
xcrun --show-sdk-path
```

```bash

```

Для сборки из Terminal полный Xcode не обязателен. При использовании Xcode
выберите его в Xcode → Settings → Locations → Command Line Tools.

## Быстрый запуск

Откройте Terminal в корне репозитория:

```bash
scripts/build-app.sh
open dist/VisioRhytm.app
```

Скрипт по умолчанию собирает release binary, формирует обычный macOS bundle
`dist/VisioRhytm.app`, добавляет Info.plist и применяет локальную ad-hoc подпись.
После сборки `.app` можно запускать из Finder и переносить в Applications.
Исходники для работы собранного приложения не нужны.

Для debug bundle:

```bash
scripts/build-app.sh debug
open dist/VisioRhytm.app
```

Подпись предназначена для локальной сборки. Developer ID, notarization,
универсальный binary и подготовка публичной дистрибуции вынесены за пределы MVP.
Повторная сборка обновляет `dist/VisioRhytm.app`; закройте приложение перед её
запуском. `dist/` и `.build/` исключены из Git.

## Сборка и запуск через Swift Package Manager

```bash
# Debug executable
scripts/swift.sh build

# Запуск без упаковки в .app
scripts/swift.sh run VisioRhytm

# Release executable
scripts/swift.sh build -c release --product VisioRhytm

# Узнать каталог binary
scripts/swift.sh build -c release --show-bin-path
```

`scripts/swift.sh` — обёртка над штатным `swift`. Она размещает кэши модулей
и SwiftPM внутри `.build/`, что позволяет собирать в окружениях с ограниченным
доступом к пользовательским кэшам. Обёртка отключает вложенный sandbox SwiftPM;
проект не содержит внешних зависимостей и package plugins.

В обычном окружении можно использовать непосредственно `swift build`,
`swift run VisioRhytm` и `swift test --disable-xctest`. Если Command Line Tools
не находят модуль Testing, используйте обёртку: она добавляет пути установленного
Testing.framework и его runtime. При отсутствии Swift Testing требуется
актуальный комплект инструментов Swift / Xcode.

## Запуск в Xcode

1. Откройте `Package.swift` через File → Open в Xcode.
2. Дождитесь загрузки локального Swift package.
3. Выберите схему `VisioRhytm` и destination **My Mac**.
4. Нажмите Run (`⌘R`).
5. Для тестов используйте Product → Test (`⌘U`).

Отдельный `.xcodeproj` не нужен. Командная сборка с `scripts/build-app.sh`
дополнительно устанавливает декларацию формата `.visiorhythm` в bundle,
поэтому для запуска проектов двойным щелчком используйте упакованное `.app`.

## Первый пользовательский сценарий

1. Запустите приложение. Новая сессия открывается с 120 BPM, 4/4, сеткой 1/8.
   Если доступно autosave, вместо нового проекта восстанавливается последняя сессия.
2. Нажмите **Загрузить пример** или вставьте текст слева:

   ```text
   Война на невидимом фронте
   Где враг растворяется в сети
   Мы строим защиту сегодня
   Чтоб завтра систему спасти
   ```

3. Нажмите **Разместить строки**. Пустые строки и текст в `[]` / `()` пропускаются, каждой новой
   дорожке назначаются два такта. Все дорожки начинаются с первого такта
   для наглядного сравнения.
4. Кнопками **1**, **2**, **4** у строки назначьте количество тактов.
   Для общей подгонки установите диапазон **Такты** сверху и нажмите
   **Подогнать строки под такты** над Canvas.
5. Двигайте slider плотности. Вправо — больше слогов на долю, короче строка;
   влево — меньше слогов на долю, больше пространства.
6. Сравните блоки, числовое значение `сл/д` и цветовые индикаторы соседних строк.
7. Нажмите **Play**: прозвучат клики, колонка и playhead начнут двигаться.
8. Измените BPM и убедитесь, что длины и позиции блоков сохраняются.
9. Сохраните проект (`⌘S`), затем проверьте его открытие (`⌘O`).

Длина блоков показывает длительность. Промежуток между словами больше,
чем между слогами одного слова; чередование оттенков помогает отличать слова.
Очень узкие блоки могут не вмещать подпись: увеличьте масштаб или откройте
редактор строки. Пунктирная вертикаль обозначает конец музыкальной области строки.

Колонки с кликами выделены фиолетовым фоном и точками в линейке.
Выделение соответствует настройкам метронома и выбранному диапазону:
без «Клики сетки» это основные доли; с ним — также subdivisions.
Сила фона отражает primary / secondary / regular / subdivision акцент.
Колонки вне диапазона остаются нейтральными. При нулевой громкости разметка
продолжает показывать запланированные клики. Бирюзовая линия и подвижная
подсветка показывают текущую позицию независимо от разметки кликов.

## Комментарии в тексте песни

Текст внутри квадратных и круглых скобок сохраняется в исходном редакторе
и JSON, но не переносится на Canvas и не учитывается в количестве слогов:

```text
[Куплет]
Война (тихо) на невидимом фронте
[Инструментальная пауза]
Где враг растворяется в сети (эхо)
```

В этом примере появляются две дорожки: «Война на невидимом фронте» и
«Где враг растворяется в сети». Строки, состоящие только из комментариев,
дорожек не создают. Поддерживаются вложенные и многострочные блоки:
`[Проигрыш (гитара)]` и комментарии, охватывающие несколько строк.
Переносы строк сохраняют разделение оставшегося текста на дорожки.
При удалении комментария между словами сохраняется пробел.

Незакрытая скобка остаётся обычным текстом, чтобы незавершённая правка
не скрывала остальную песню. Исправить её можно в общем редакторе.
Изменение Bars, Density или Reset сохраняет комментарии, пустые строки
и остальной исходный текст. Редактирование отдельной дорожки меняет
соответствующую исходную строку; многострочные комментарии пересчитываются
для всех затронутых соседних строк.

## Редактирование текста и слогов

Нажмите значок карандаша у строки или саму дорожку. В редакторе можно изменить
исходный текст и выбрать ручное разбиение.

Пример ручных границ:

```text
Вой|на на не|ви|ди|мом фрон|те
```

Внутри слова используйте `|`, между словами — пробелы. Слова, регистр букв
и пунктуация должны совпадать с текстом вне `[]` и `()`.
Содержимое скобок в поле ручных границ вводить не нужно. Пустые слоги и случайное
изменение слова отклоняются с объяснением. Дефис исходного текста сохраняется
как обычный символ; служебным разделителем является только `|`.

**Получить автоматическое разбиение** обновляет поле границ по текущему тексту,
а **Применить** сохраняет изменения. Кнопка reset у строки повторно выполняет
автоматическое слогоделение и равномерную раскладку, убирает ручные границы,
но сохраняет музыкальную длину строки.

При повторном применении общего текста совпадающие строки сохраняют свои
настройки и ручные границы. Новые или изменённые строки получают два такта.
Правки в общем текстовом поле являются черновиком до нажатия «Разместить строки»;
обычное сохранение проекта также применяет этот черновик. Autosave хранит только
подтверждённое состояние. Неприменённый черновик учитывается в запросе сохранения
при выходе и замене проекта. Изменение плотности не стирает черновик.

## Музыкальное время и плотность

BPM всегда означает **четвертные ноты в минуту**, в том числе в 6/8 и 12/8.
Поэтому при 120 BPM в 6/8 основные восьмые доли звучат через 0,25 секунды,
а весь такт длится 1,5 секунды. Акцент 6/8 располагается на долях 1 и 4;
12/8 — на 1, 4, 7 и 10. В 4/4 основной акцент — на 1, вторичный — на 3.

Сетка задаёт визуальную детализацию и опциональные клики subdivisions.
Если она крупнее основной доли размера, основные доли всё равно показаны
и озвучены: например, все шесть долей 6/8 остаются доступными с сеткой 1/4.
Автоматическая раскладка равномерна в ticks и не округляет слоги к сетке.

Единственный источник длины строки — `rhythmicLength.ticks`. Плотность вычисляется:

```text
syllablesPerBeat = количество слогов × ticks одной доли / длина строки в ticks
```

Slider задаёт 0,25–6 слогов на долю; длительность ограничена 32 тактами.
Поэтому у крайних значений для очень короткого или длинного текста фактическое
значение может отличаться от диапазона slider. Точное значение показывается рядом.
Кнопки 1/2/4 такта и slider меняют один параметр длины; после slider число тактов
может быть дробным.

Кнопка **Подогнать строки под такты** назначает всем дорожкам длину выбранного
диапазона и размещает их от его начала до конца. Например, диапазон **5–8**
означает четыре такта: все строки начинаются с пятого и заканчиваются перед
девятым. Слоги распределяются равномерно, плотность пересчитывается отдельно
для каждой строки по её количеству слогов. Поэтому строки разной длины текста
сохраняют разные значения слогов на долю.

Подгонка работает в обоих режимах playback и учитывает текущий музыкальный
размер. Она сохраняет исходный текст, комментарии и ручные границы слогов,
но заменяет предыдущие позиции и длительности равномерной раскладкой.
Неприменённый черновик в общем редакторе сохраняется; кнопка действует на
уже размещённые дорожки. Если дорожек нет, кнопка недоступна. После изменения
диапазона для новой подгонки нажмите её повторно.

Кнопка **Сбросить подгонку** находится рядом и возвращает начало, длину и
расположение слогов до первой подгонки. Повторные подгонки сохраняют эту исходную
раскладку. После сброса плотность вычисляется по восстановленной длине строки;
выбранный диапазон воспроизведения остаётся текущим.

Сброс сохраняет последующие изменения текста, комментариев, ручных границ и
неприменённый черновик. Если слоги изменились, они равномерно распределяются
в прежней длине строки; если сохранились, восстанавливаются точные позиции и
длительности. Удалённые строки не возвращаются. Новые строки восстанавливаются,
если они участвовали в последующей подгонке. Если изменённый текст не помещается
в прежнюю длину, операция целиком отменяется с сообщением: сократите текст и
повторите сброс.

Исходная раскладка для сброса хранится в текущей сессии приложения и не записывается
в JSON. После открытия или создания проекта, перезапуска приложения и успешного
сброса кнопка недоступна до следующей подгонки. Сохранение текущего проекта
во время сессии сохраняет возможность сброса.

Кнопка использует весь выбранный диапазон до 256 тактов; ограничение в 32 такта
относится к slider плотности. Если диапазон не позволяет назначить каждому
слогу хотя бы минимальную музыкальную длительность, появится сообщение
с номером строки. В этом случае увеличьте число тактов: подгонка применяется
ко всем строкам одновременно, без частичного изменения проекта.

Категории служат ориентиром: менее 1 слога/долю — «Свободно», от 1 до 2 —
«Умеренно», от 2 до 3 — «Плотно», от 3 — «Очень плотно». Это условные пороги,
а не правила написания песни. В составных размерах «доля» здесь соответствует
знаменателю, поэтому сравнивайте показатели внутри выбранного размера.

При смене размера сохраняются ticks строк и слогов. Меняется сетка,
количество тактов для существующей длины и значение слогов на долю.
Например, два такта 4/4 превращаются в 2,67 такта 6/8 с теми же позициями.
Чтобы назначить новой строке ровно два такта нового размера, нажмите кнопку **2**.

## Метроном, цикл и синхронизация

- **Play** начинает или продолжает метроном с сохранённой позиции.
- **Stop** останавливает звук и сохраняет текущую позицию.
- **Return** возвращает к началу; если Play активен, воспроизведение продолжается.
- **Такты** задают диапазон воспроизведения в обоих режимах. Такты задаются включительно:
  `5–8` означает начало пятого такта до начала девятого.
- **Цикл** включает повтор выбранного диапазона.
- Return переходит к первому такту диапазона. Если сохранённая позиция
  находится вне диапазона, Play также начинает с первого такта диапазона.
- Без цикла метроном проигрывает диапазон один раз и автоматически останавливается
  после последнего выбранного такта. Звук обрывается точно на музыкальной границе,
  курсор остаётся на ней, транспорт показывает «Конец». Следующий Play повторяет диапазон.
- Стрелки «Такты» действуют и при выключенном цикле, включая изменения во время Play.
  При сокращении диапазона до позиции, которая уже пройдена, playback останавливается.
- Диапазон ограничен 1–256 тактами. Canvas расширяется до конца строк
  или выбранного диапазона. Выбранные такты выделены в линейке, их границы
  показаны вертикалями. Строки за пределами диапазона сохраняются.
  Автоматическое следование за playhead не реализовано.
- **Клики сетки** добавляют тихие клики subdivisions; основные доли звучат всегда.

В render callback AVAudioSourceNode позиция клика вычисляется из абсолютного
номера аудиосэмпла. Интервалы не суммируются с округлением, поэтому ошибка
периода не накапливается. Тот же PlaybackPlan переводит sample position в ticks
для UI. Render timestamp привязывает frame counter к host clock; при показе
позиции учитывается `outputNode.presentationLatency`.

TimelineView лишь запрашивает новую отрисовку — до 60 раз/с для Canvas.
Он не определяет музыкальное время и не увеличивает счётчик позиции.
При задержке UI или недоступном кадре визуализация догоняет аудиочасы,
а не продолжает собственный таймер.
На время playback приложение удерживает ProcessInfo activity, предотвращающую
App Nap и автоматический сон системы; после Stop activity освобождается.

Смена BPM, размера, цикла или режима кликов во время playback пересоздаёт
аудиодвижок с сохранением позиции в ticks. В момент изменения возможна короткая
пауза; между изменениями playback непрерывен. При смене аудиоустройства
воспроизведение останавливается и появляется сообщение: снова нажмите Play.
Задержка Bluetooth и конкретного устройства может влиять на воспринимаемое
смещение — проверяйте синхронизацию на используемом выводе звука.
Громкость меняется на mixer без перезапуска аудиодвижка.

## Проекты и autosave

Проект — UTF-8 JSON с расширением `.visiorhythm`. Также можно открыть JSON
через диалог. Формат содержит `version: 1`, UUID проекта, название, BPM,
размер, subdivision, полный текст, строки, слоги, позиции, длительности,
ручные границы и настройки метронома. Seconds и пиксельные координаты
не сохраняются. Масштаб — временная настройка UI.

Старые JSON версии 1, в которых комментарии уже входили в слоги,
открываются с автоматическим исключением комментариев. Исходный текст,
ID и музыкальная длина оставшихся дорожек сохраняются. Дорожки, которых
изменение не касается, сохраняют слоги и ручные позиции. Затронутые дорожки
распределяются заново; ручные границы сохраняются, если подходят к тексту
без комментариев. Формат JSON остаётся версии 1.

Файл версии, отличной от 1, отклоняется до декодирования его схемы.
Проверяются диапазоны параметров, уникальность ID, соответствие слогов словам
и границы длительностей. Открытие повреждённого файла не заменяет текущий проект.
Сохранение выполняется атомарно.

Autosave записывается через 600 мс после изменения подтверждённого проекта:

```text
~/Library/Application Support/VisioRhytm/Autosave.visiorhythm
```

Последняя сессия восстанавливается при следующем запуске с информационной
полосой. Autosave — отдельная рабочая копия; он не перезаписывает вручную
сохранённый файл и не восстанавливает привязку к нему. После восстановления
выберите место обычного сохранения. Последняя подтверждённая сессия сохраняется
и при нормальном выходе, даже если выбран выход без сохранения в файл проекта.
Неприменённый текстовый черновик при таком выходе не сохраняется.

Повреждённый autosave не удаляется при старте. Приложение сообщает об ошибке
и открывает пустую сессию; при следующих изменениях создаётся новое autosave.
Для полного сброса рабочей сессии закройте приложение и переместите этот файл
в другое место либо создайте «Новый проект».

## Архитектура

```text
Package.swift
Sources/
  VisioRhytmCore/
    Domain/Models.swift              Project, LyricsLine, Syllable, time types
    RhythmEngine/RhythmEngine.swift  ticks, BPM, density, accents, PlaybackPlan
    LyricsEngine/LyricsEngine.swift  parsing, service, syllabification, layout
    ProjectStore/ProjectStore.swift  JSON, validation, atomic IO
  VisioRhytmAudio/
    MetronomeEngine.swift           AVAudioEngine, source rendering, clock
  VisioRhytm/
    VisioRhytmApp.swift             app lifecycle, document menus
    UI/AppState.swift              Observation state, commands, autosave
    UI/MainWindow.swift            transport, settings, editor, controls, inspector
    UI/RhythmCanvas.swift          grid, tracks, blocks, playhead
Tests/
  VisioRhytmCoreTests/CoreTests.swift
  VisioRhytmAudioTests/AudioTests.swift
Resources/Info.plist
scripts/swift.sh
scripts/build-app.sh
```

`VisioRhytmCore` не зависит от SwiftUI или AVFoundation. `VisioRhytmAudio`
зависит только от Core и системных audio API. SwiftUI-приложение зависит от
обоих модулей; Canvas переводит ticks в координаты через масштаб и не является
источником музыкального состояния.

`SyllabificationService` заменяем: другой язык можно добавить отдельной
реализацией без изменения Canvas. Syllable хранит относительную позицию внутри
строки, LyricsLine — абсолютную позицию начала. Типы содержат поля для будущих
ударений и весов длительности; MVP их автоматически не определяет.

Внутренний PPQ = 480: четверть — 480 ticks, восьмая — 240,
шестнадцатая — 120. Пользователь видит такты и доли.

## Проверки

Основной набор:

```bash
scripts/swift.sh test
```

Проверка команд интерфейса, включая подгонку строк:

```bash
scripts/swift.sh test --filter VisioRhytmUITests
```

Для версии 0.1.4 этот набор прошёл: подгонка и её сброс проверены во всех четырёх размерах,
в том числе для диапазона 5–8, сохранения ручных границ, комментариев,
неприменённого черновика и JSON round-trip. Проверена также отмена всей операции
при недостаточной длине диапазона. Дополнительно проверены точное восстановление
неравномерной раскладки, повторные подгонки и сбросы, сохранение правок текста,
обработка новых и удалённых строк и повторный сброс после исправления ошибки.

Тесты проверяют размеры и единицы, конвертацию BPM, независимость layout от BPM,
сохранение символов слогоделением, CRLF и пустые строки, равномерное распределение,
плотность, ручные границы, JSON round-trip с ручными позициями, атомарную запись,
некорректные и будущие версии файлов, акценты, цикл, синтез и возобновление кликов.

Десятиминутная модель sample clock проверяется на 40/137/240 BPM при
44,1/48/96 кГц. Отдельный offline-тест пропускает более 100 тысяч сэмплов
через AVAudioEngine и сравнивает результат с общей моделью синтеза.
Даже offline-render требует доступа к системным компонентам CoreAudio;
ограниченный sandbox может блокировать их создание.

Для трёхминутной проверки часов на реальном устройстве вывода:

```bash
VISIORHYTM_LIVE_AUDIO_TEST=1 scripts/swift.sh test --filter liveAudioClockAndTransport
```

Тест запускает AVAudioEngine с **нулевой громкостью**, проверяет продвижение
позиции по audio clock каждые 10 секунд, остановку, Return, цикл 5–8 и смену BPM.
Отклонение относительно контрольных монотонных часов должно оставаться меньше
60 мс. Этот тест по умолчанию пропускается, поскольку требует устройства вывода.

Короткая проверка исправления однократного playback и диапазона:

```bash
VISIORHYTM_TRANSPORT_TEST=1 scripts/swift.sh test --filter singlePassStopsWithoutUIAndCanReplay
```

Она проверяет автоматическую остановку без работающего Canvas, повторный Play,
Return, отключение цикла во время воспроизведения и сокращение диапазона.

Автотесты часов не заменяют проверку слышимого клика и видимой подсветки.
Ручная приёмка:

1. С примером lyrics запустите 120 BPM / 4/4 / 1/8 на 3–5 минут.
2. Проверьте совпадение слышимых кликов и текущих колонок в начале и конце.
3. Повторите для 6/8, тихих subdivision-кликов и цикла 5–8.
4. Проверьте 40 и 240 BPM, Stop/Play/Return, смену устройства вывода.
5. Измените density и 1/2/4 такта; смените BPM — блоки должны остаться на месте.
6. Исправьте границы слогов, сохраните и откройте проект, проверьте восстановление.
7. Проверьте zoom, scroll и светлую/тёмную тему на вашем дисплее.

## Устранение проблем

Проверка версии 0.1.2: 33 теста прошли, включая фильтрацию скобок,
редактирование исходного текста, загрузку старых проектов, разметку кликов,
offline AVAudioEngine и короткий тест однократного playback на устройстве вывода.
Длительный тест в этом прогоне пропущен. В отдельной трёхминутной проверке
первой версии на 180-й секунде отклонение аудиочасов от контрольных
монотонных часов составило около 0,6 мс.
Проверены Info.plist, подпись bundle и запуск видимого SwiftUI-окна 1440 × 880.
Ручная проверка воспринимаемой
синхронизации по слышимому клику и видимой подсветке остаётся необходимой.

**Swift не может записать кэш или сообщает о SwiftShims.** Используйте
`scripts/swift.sh`, который переносит кэш в `.build/`. Если ошибка о несовместимости
SDK остаётся, убедитесь, что выбранные toolchain и SDK принадлежат одному комплекту
Command Line Tools / Xcode.

**Нет модуля Testing.** Используйте обёртку. Если Testing.framework действительно
отсутствует в установленных инструментах, обновите Command Line Tools или Xcode.

**Метроном не запускается.** Проверьте System Settings → Sound → Output.
Приложение не запрашивает микрофон. Запускайте его в обычной пользовательской
сессии macOS, с доступом к CoreAudio, а не в изолированном CI sandbox.

**Нужны другие такты.** Измените стрелками диапазон «Такты». Он действует
с включённым и выключенным циклом; выбранная область выделена в линейке Canvas.
После окончания однократного playback Play повторяет диапазон, Return возвращает
к его началу.

**Слог не помещается.** Увеличьте zoom, музыкальную длину строки или откройте
редактор для чтения полного текста. Менять исходный текст для этого не требуется.

## Границы MVP

Русское слогоделение эвристическое: словарь, ударения и точное лингвистическое
деление не реализованы. Предлоги без гласных и пунктуация сохраняются как
визуальные текстовые элементы. Пустые строки не создают секции.

Ручное редактирование MVP касается границ слогов. Drag/stretch, snap, перемещение
между тактами, произвольные паузы, undo/redo и section markers запланированы
после MVP. Сейчас автоматическая раскладка не прогнозирует длительность
отдельных слов или исполнение певца.

Практические лимиты: 100 000 символов lyrics, 500 строк, 2 000 элементов в строке,
20 МБ на файл проекта, конец строки до 1 000 000 ticks. Большие проекты требуют
дальнейшего профилирования. MIDI, нотная запись, pitch, синтез вокала, генерация
музыки, запись звука и экспорт аудио отсутствуют.
