# VisioRhytm: MVP и целевая архитектура

Разработка идёт от музыкальной модели к аудиодвижку и затем к UI.
Статусы обновляются после сборки и проверок, а не по наличию заглушек.

## MVP

- [x] Domain: versioned Project, musical ticks (PPQ 480), независимые позиции и длительности.
- [x] RhythmEngine: размеры 4/4, 3/4, 6/8, 12/8; сетки 1/4, 1/8, 1/16; BPM 40–240.
- [x] MetronomeEngine: аудиорендер, primary/secondary/regular/subdivision клики, громкость.
- [x] Audio clock: единый источник позиции для звука и визуализации; без музыкального Timer.
- [x] LyricsEngine: строки, слова, эвристическое русское слогоделение.
- [x] Ручная корректировка границ слогов с сохранением исходного текста.
- [x] Автоматическая равномерная раскладка по ticks.
- [x] SwiftUI Canvas: такты, доли, subdivisions, номера, колонки и playhead.
- [x] Индивидуальные 1/2/4 такта, непрерывная плотность, редактирование и reset строк.
- [x] Нейтральная оценка плотности и сравнение соседних строк.
- [x] BPM не меняет layout; размер меняет сетку, сохраняя позиции.
- [x] Scroll и zoom.
- [x] Play/Stop/Return, цикл по выбранным тактам.
- [x] Codable JSON, проверка версии и входных данных, save/open, локальное autosave.
- [x] Сборка debug/release, тесты модели, раскладки, persistence и аудиочасов.
- [x] README: требования, сборка .app, запуск, пользовательский сценарий, ограничения.
- [ ] Проверка слухом и глазами на реальном аудиоустройстве после нескольких минут playback.

## Целевая архитектура

- [x] Domain остаётся независимым от SwiftUI и AVFoundation.
- [x] RhythmEngine — единственное место расчётов ticks, beats, bars, BPM и density.
- [x] LyricsEngine использует заменяемый SyllabificationService для новых языков.
- [x] MetronomeEngine владеет audio render clock; UI лишь читает musical position.
- [x] ProjectStore отвечает за версионирование, валидацию и атомарное сохранение.
- [x] UI: MainWindow, TransportBar, RhythmSettingsPanel, LyricsEditor, RhythmCanvas,
  LyricsTrack, SyllableBlock, LineControls, Inspector.
- [x] VisioRhytmRhyme: независимый от UI HTTP-клиент, настройки, промпты и контекст.
- [x] RhymeAssistant: Observation-состояние, отмена и защита от устаревших ответов.
- [x] NSTextView-мост: подсказка у курсора и стандартный Undo текстовых правок.

## После MVP

- [x] Помощь с рифмой через Ollama: см. отдельный план ниже.
- [ ] Drag/stretch слогов, паузы и переносы: ticks + snap Off/1/4/1/8/1/16.
- [ ] Undo/redo и история ручной раскладки.
- [ ] Ударения; улучшение русской эвристики; сервисы других языков.
- [ ] Section markers Verse/Chorus/Bridge и сохранение пустых строк как секций.
- [ ] Статистика сравнений, групповые операции со строками.
- [ ] Экспорт click track / аудио и AI-specific presets.
- [ ] Миграции будущих версий JSON.
- [ ] Дистрибуция: иконка, Developer ID, notarization, универсальный binary, CI.
- [ ] Профилирование долгих проектов, доступность VoiceOver, UI-автотесты.

MIDI, pitch, ноты, гармония, DAW, вокальный синтез и сетевые AI-сервисы
не входят в MVP.

## Ollama: завершение рифмы

- [x] Галочка помощи; подсказки у курсора после паузы в наборе.
- [x] Анализ текущей строки; пунктуация, пустые строки, комментарии, выделение и IME отключают подсказку.
- [x] Число вариантов, модель, строки до/после и задержка запросов.
- [x] Редактируемый системный промпт по умолчанию и возврат к исходному.
- [x] Строгий JSON для вариантов и сжатия; никакого автоматического изменения текста.
- [x] Настройки URL, num_ctx, num_predict, temperature, top_k, top_p, min_p,
  repeat_penalty, repeat_last_n, seed, stop, keep_alive и режима thinking.
- [x] Получение списка моделей и проверка соединения без скачивания моделей.
- [x] Полный текст + история генераций, полоса заполнения контекста, кнопка сжатия.
- [x] Сжатие длинной истории порциями, без обрезания текста песни.
- [x] Отмена запросов, защита от устаревших ответов и сохранение контекста при ошибке.
- [x] Вставка выбранного окончания, Undo, Tab/Esc, сохранение текста и комментариев.
- [x] Локальное сохранение настроек; история не переносится между проектами.
- [x] Тесты транспорта, Unicode, триггеров, контекста, сжатия, отмены и вставки.
- [x] README: настройка Ollama, сценарии, параметры, JSON и ограничения.
- [x] Release-сборка 0.2.0 (build 10), Info.plist и ad-hoc подпись проверены.
- [x] Реальный Ollama localhost:11434: qwen3.5:4b, JSON-окончания и JSON-сжатие.

## Исправление длинных генераций Ollama — 0.2.1

- [x] Воспроизведена аномалия на Ollama 0.35.0 / qwen3.5:4b: автоматический
  Thinking и Max tokens = 5000 дают 5000 токенов / 19 039 символов рассуждений
  за 85 секунд, пустой JSON-ответ и завершение по лимиту.
- [x] Thinking по умолчанию выключен явно в HTTP-запросе; старое автоматическое
  значение мигрируется без потери модели, промпта и остальных параметров.
- [x] Бюджет окончаний зависит от числа вариантов: min(Max tokens, 64 + 64 × N),
  одинаково в обоих режимах; для трёх вариантов максимум 256 токенов.
- [x] Каждый вариант ограничен 80 символами и восемью словами в запросе и проверке;
  схема также ограничивает длину, неподходящие варианты отклоняются целиком.
- [x] История хранит компактный JSON проверенных вариантов, без сырого ответа и Thinking.
- [x] Полоса контекста резервирует фактический бюджет завершения вместо сохранённого Max tokens.
- [x] Сжатие всегда выключает Thinking, ограничено 512 токенами и проверяет длину резюме.
- [x] Диагностика отдельно учитывает рассуждения; ошибки больше не советуют увеличивать
  лимит для исчерпанного рассуждениями ответа.
- [x] Регрессии старых настроек, двух режимов, 1/3/10 вариантов, длинных ответов,
  истории и явного включения Thinking; набор из 70 тестов прошёл с нативным редактором.
- [x] Реальные JSON-запросы: 32 токена для соседних строк, 23/25 для полной песни
  и истории, 79 для сжатия; Thinking отсутствует во всех ответах.
- [x] README обновлён: причина аномалии, ограничения, миграция и проверки.
- [x] Release-сборка 0.2.1 (build 11), версия bundle и ad-hoc подпись проверены.
